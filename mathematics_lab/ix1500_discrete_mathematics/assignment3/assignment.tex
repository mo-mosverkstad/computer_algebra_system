\begin{abstract}

This report concerns the Quadratic Sieve algorithm, an integer factorization algorithm based on modular arithmetic and quadratic remainders. Mathematical concepts as a fundament to the algorithm as well as its underlying subalgorithms such as Tonelli-Shanks algorithm are explained. This includes generation of smooth numbers, the construction of a factor base, and the use of linear algebra to find a congruence of squares. Additionally, a working prototype is also used to illustrate the algorithm, as well as the strengths, limitations, and practical applications are discussed.

\end{abstract}

\section*{Introduction}

This report concerns Quadratic Sieve algorithm which is an integer factorization algorithm for factoring large integers. Integer factorization is an important computational problem for different applications in number theory and cryptography. The Quadratic Sieve approaches the factorization problem by searching for a congruence between two squares, which can then be used to obtain a non-trivial factor of the original integer. For Quadratic Sieves, a factor base are constructed for series of quadratic differences and smooth values are also searched. Linear algebra is used at last to find suitable relations between these values. The correctness of the method can be explained through the resulting congruence of squares. A prototype for demonstrating the method on relatively small composite numbers is also implemented.

\section*{Problem}
% 1. Problem Definition: Clearly define the problem and explain its significance.

The problem scope of the Quadratic Sieve concerns the factorization of a composite number into non-trivial factors. This is important for different applications in number theory and cryptography. In terms of cryptography, the difficulty of factoring large number serves as a base for cryptographic security. 

Given a composite integer $N$, the factorization problem is to find integers $p$ and $q$ such that

\[
N = pq,
\]

where $1 < p,q < N$. For a sufficiently large composite number, finding such factors can become computationally difficult. Simple algorithms such as trial-division that tests all prime numbers can quickly become a bottleneck since the algorithm has to check the prime number $2$ and all odd numbers since all prime numbers except $2$ are odd, up to $\sqrt{N}$.

The Quadratic Sieve solves this problem by searching for a congruence of squares modulo $N$,

\[
x^2 \equiv y^2 \pmod{N}
\]

where $x \not\equiv \pm y \pmod{N}$. By solving the modular equation into the given congruence between $x$ and $y$, a non-trivial factor of $N$ can be obtained through the greatest common divisor,

\[
\gcd(x-y,N) \quad \text{or} \quad \gcd(x+y,N)
\]

In order to efficiently find the suitable values $x$ and $y$, the algorithm generates quadratic differences and searches for smooth values that can be represented using only small prime factors with even exponents. In this case, a pair of $x$ and $y$ can be found, whereas gcd can be calculated. This avoid searching through all $\lfloor \sqrt{N}/2 \rfloor + 1$ candidate numbers during factorization.

\section*{Mathematical Background}
% 2. Mathematical Background: Introduce the mathematical concepts, definitions, and theorems needed to understand the problem.

The Quadratic Sieve algorithm relies on several concepts in both number theory and linear algebra. Linear algebra is included in the algorithm since it has a clean property of batch-solving multiple linear expression.

\subsection*{Modular Arithmetic}

The most important backbone concept that the Quadratic Sieves algorithm relies on is modular arithmetics. For two integers $a$ and $b$, the congruence 

\[
a \equiv b \pmod{N}
\]

means that the residue for the division $a/N$ is the same as for $b/N$. It also means that $N$ divides their diverence

\[
N \mid (a-b)
\]

In this case, the expression can also be transformed into a linear equation without special mathematical symbols:

\[
a - b = N \times k
\]

\subsection*{Quadratic Residues}

An integer $a$ is a quadratic residue modulo $N$ if an integer $x$ exists and fulfills

\[
x^2 \equiv a \pmod{N}
\]

In another words, this can also be rephrased that if $a$ is an quadratic residue modulo $N$, the previous equation produces at least a solution $x$.

If an integer $a$ is not a quadratic residue, it is called instead a quadratic non-residue modulo $N$.

Quadratic residues are important for Quadratic Sieve algorithm since  the algorithm checks every quadratic difference $x^2 - N$ to be divisable by a prime number $p$. This problem can be rewritten as $x^2 \equiv N \pmod{p}$, whereas similar rewrite is mentioned above in Modular Arithmetic. Solving such modular equation requires Tonelli-Shanks algorithm, which will be investigated in detail later.

\subsection*{Euler's criterion}

Euler's criterion is an important property to check if a given integer number $a$ is a quadratic residue modulo an odd prime $p$. The property is useful in Tonelli-Shanks algorithm. 

For $a \not\equiv 0 \pmod p$, it states that
\[
a^{(p-1)/2} \equiv
\begin{cases}
1 \pmod p, & \text{if } a \text{ is a quadratic residue}\\
-1 \pmod p, & \text{otherwise, } a \text{ is not a quadratic residue}
\end{cases}
\]

Using this property, whether an integer $a$ has a square root modulo $p$ can be tested, in order to determine if a modular square root exists.

This property can be simply proven by applying Fermat's little theorem

\[
x^{p-1} \equiv 1 \pmod p
\]

which can be rewritten using conjugate rule:
\[
a^{p-1} - 1 = (a^{(p-1)/2} - 1)(a^{(p-1)/2} + 1) \equiv 0 \pmod p
\]

Since $p$ is prime, this implies
\[
a^{(p-1)/2} \equiv 1 \pmod p
\qquad\text{or}\qquad
a^{(p-1)/2} \equiv -1 \pmod p.
\]

If $a$ is a quadratic residue modulo $p$, this means that $y$ fulfilling $a \equiv y^2 \pmod p$ can be rewritten as

\[
a^{(p-1)/2}
\equiv
(y^2)^{(p-1)/2}
=
y^{p-1}
\equiv 1 \pmod p,
\]
where the last congruence applies Fermat's little theorem.

Consequently, the reversed also applies. Given $a^{(p-1)/2} \equiv 1\pmod p$, $a$ can be derived as a quadratic residue. Constructing a polynomial $f(x)=x^{(p-1)/2}-1$, it has the degree $(p-1)/2$ and can have at most $(p-1)/2$ roots modulo the prime $p$. Since every non-zero quadratic residue  $a$ satisfies
\[
a^{(p-1)/2}\equiv 1\pmod p,
\]
there are exactly $(p-1)/2$ distinct nonzero quadratic residues modulo $p$, since
\[
1^2,2^2,\ldots,\left(\frac{p-1}{2}\right)^2
\]
are all distinct modulo $p$ and these nonzero quadratic residues are exactly the roots of $f(x)$.
\[
a^{(p-1)/2}\equiv 1\pmod p
\]
if and only if $a$ is a quadratic residue modulo $p$.
Combining this result with
\[
a^{(p-1)/2}\equiv \pm1\pmod p,
\]
Euler's criterion can be obtained.


\subsection*{Smooth Numbers}

Another important concept is smooth number. A number is called smooth, or specifically $B$-smooth, if all its prime factors are smooth, which is essentially less than or equal to $B$. For instance, the number $2^3\times 3 \times 5 = 120$ is $5$-smooth since its prime factors after prime factorization are less than the bound $5$. However, a number $5 * 23 = 115$ is not $5$-smooth since it contains a prime factor $23$ which is over the bound.

Smooth numbers are important for Quadratic Sieve algorithm because each element of the exponent vector corresponds to a ordered factored prime base starting from $2$, for instance the base ($2$, $3$, $5$, $7$, $11$, $\cdots$). Prime exponent vectors for smooth quadratic differences $x^2 - N$ must not be arbitrary large, otherwise computational performance will be affected. This means that a bound for the prime numbers must be set to limit the length of prime exponent vectors.

\subsection*{Factor Base and Exponent Vector}

A factor base is a basis concept suitable for linear algebra. In this specific vector space, each number can be represented as an exponent vector where each element is an exponent corresponding to each prime base in a factor base. Notice that each number has a unique exponent vector due to The Fundamental Theorem of Arithmetic.

Suppose that a basis can be written as:

\[
\mathcal{B}=\{p_1,p_2,\ldots,p_k\}
\]

then a smooth number in basis $\mathcal{B}$ can be written as, considering the number can be represented as ($e_0$, $e_1$, $e_2$, $\cdots$, $e_k$) in vector-form:

$$
n = (-1)^{e_0}p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k}
$$

Notice how $e_0$ correspond to the sign, where an even sign produces positive number, while odd sign for negative number.

For instance, a number $n_1 = 24$ can be written as the exponent vector $v_1 = (3, 1, 0)$ over the factor base $\mathcal{B}=\{2, 3, 5\}$.

Factor bases are however not bases for linear general vector spaces. In a conventional linear vector space, applying a linear combination implies scaling vectors via scalar multiplication and combining them via vector addition. However, in this particular case, applying a linear combination to the exponent vectors corresponds to exponentiation and multiplication of the underlying prime bases instead. Operators for exponent vectors are one level lower than operators for equivalent numbers, meaning that an addition of two exponent vectors correspond to a multiplication of two numbers.

Since the parity of each exponent is sufficient to determine if a product of numbers in exponent vector form, these vectors can be considered existing in the Galois field 2 $\mathbb{F}_2$. Exponent vectors over $\mathbb{F}_2$ may not be unique for each number, but facilitates computation for searching perfect squares.

\subsection*{Linear Algebra over $\mathbb{F}_2$}

Despite that factor bases are not linear bases for linear vector spaces, the exponent vectors can still be used in linear algebra. Multiplication of two integer numbers can be represented as addition between two exponent vectors.

Exponent vectors over Galois Field $\mathbb{F}_2$ becomes interesting for calculating perfect squares.

Considering an integer $n$, having the prime factorization:

$$
n = (-1)^{e_0} p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k}.
$$

Its corresponding exponent vector on $\mathbb{F}_2$ is

$$
(e_0\bmod 2, e_1\bmod 2, e_2\bmod 2,\ldots, e_k\bmod 2)
$$

If $n$ is a perfect square, its exponent vector on $\mathbb{F}_2$ is of all zeros, since zero corresponds to an even exponent. If all prime exponents are odd, the number can be considered as a perfect square.

Finding a product that is a perfect square from a set of numbers $\{n_1, n_2, n_3, \ldots, n_k\}$ can be solved using linear algebra. The integer numbers $\{n_1, n_2, n_3, \ldots, n_k\}$ can be written as a set of prime exponent vectors on $\mathbb{F}_2$. These vectors can be formed into a matrix 

\[
A =
\begin{pmatrix}
e_{11} & e_{12} & \cdots & e_{1k} \\
e_{21} & e_{22} & \cdots & e_{2k} \\
\vdots & \vdots & \ddots & \vdots \\
e_{m1} & e_{m2} & \cdots & e_{mk}
\end{pmatrix}
\pmod{2}
\]

where $m$ is number of prime exponents used for the numbers. To specify which integers should be multiplied together, a selection vector

\[
\mathbf{x} =
\begin{pmatrix}
x_1 \\
x_2 \\
\vdots \\
x_m
\end{pmatrix},
\qquad x_i \in \mathbb{F}_2 = \{0,1\}
\]

can be introduced. The value $n_i = 1$ indicates that the number in position $i$ is included in the product, while $n_i = 0$ indicate that the number is absent from the product. As mentioned before, since multiplying two integer numbers is equivalent for adding two corresponding prime exponent vectors, multiplying the transpose of the matrix $A$ by the selection vector gives the result in prime exponent vector:

\[
A^T \mathbf{x}
\]

For computing a perfect product square, the matrix product must be zero vector, if all prime exponent vectors belong to $\mathbb{F}_2$.

\[
A^T \mathbf{x} = 0
\]

This system can be later solved using Gaussian elimination over $\mathbb{F}_2$. Since the only elements of $\mathbb{F}_2$ are $0$ and $1$, addition is performed modulo $2$. In particular, this means that

\[
0+0=0,\qquad
0+1=1,\qquad
1+0=1,\qquad
1+1=0
\]

This means that addition in $\mathbb{F}_2$ is equivalent to the XOR operation. Gaussian elimination over $\mathbb{F}_2$ can therefore be implemented efficiently using XOR operations instead of the usual arithmetic operations.

\subsection*{Tonelli-Shanks Algorithm}

Finally, Tonelli-Shanks is a separate algorithm that is used in the Quadratic Sieves to check which numbers having quadratic residues. The purpose of this algorithm is used to find a solution to the quadratic residue equation

\[
x^2 \equiv a \pmod{p}
\]

when $p$ is an odd prime and $a$ is a quadratic residue modulo $p$. Such modular square roots can be used when determining which values in the sieving interval can produce factors belonging to the factor base.

The Tonelli-Shanks algorithm works by first decomposing $p-1$ into factors, one odd part $Q$ and $S$ as an exponent to $2$

\[
p-1 = Q \times 2^S,
\]

where $Q$ is odd. It then finds a quadratic non-residue $z$ modulo $p$ and uses repeated modular exponentiation to construct a square root of $a$.

The algorithm begins with two checks:

\begin{enumerate}
    \item If $a$ is congruent to $0$, the root is trivial and is $x=0$ for $a \equiv 0 \pmod p$. The root can be returned immediately.
    \item The value $a$ can also be checked if a quadratic residue modulo $p$ exists using Euler's criterion:
    \[
        a^{(p-1)/2} \equiv 1 \pmod p.
    \]
    If $a^{(p-1)/2}$ is modular to $-1$ with prime $p$, no root can be found and the algorithm can be exited immediately.
\end{enumerate}

Afterwards, the algorithm begins by setting up initial variables that are used for the iterations of the algorithm.

\begin{enumerate}
    \item A minimal quadratic non-residue $z$ modulo $p$ is found should be found, or with other words:
    \[
        z^{(p-1)/2} \equiv -1 \pmod p.
    \]
    \item The initial guess of the root $R$ is initialized to
    \[
        R=a^{(Q+1)/2} \pmod p
    \]
    \item The error multiplier $t$ is initialized to
    \[
        t=a^Q \pmod p
    \]
    \item The tracking exponent $M$ is also initialized to the same value as $S$:
    \[
        M=S
    \]
    \item Lastly, the so-called "Fudge factor" $c$ is initialized as:
    \[
        c=z^Q \pmod p
    \]
\end{enumerate}


The algorithm is an approaching algorithm where it loops though iterations until the desired root to the quadratic modular equation is found. When $t$ is modular with $1$ modular to the odd prime $p$, in other words $t \equiv 1 \pmod p$, the loop can be stopped.

For each iteration in the algorithm, the following steps are performed.
\begin{enumerate}
 
    \item The smallest integer $i$ is found for the modular equation:
    \[
        t^{2^i} \equiv 1 \pmod p.
    \]

    \item Afterwards, an intermediate factor $b$ is set to:
    \[
        b=c^{2^{M-i-1}} \pmod p.
    \]

    \item The variables $R$, $t$, $c$ and $m$ are updates accordingly:
    \[
        \begin{aligned}
            R &= Rb \pmod p,\\
            t &= tb^2 \pmod p,\\
            c &= b^2 \pmod p,\\
            M &= i.
        \end{aligned}
    \]

\end{enumerate}

The algorithm therefore returns one of the two possible square roots of $a$ modulo $p$. The other root is given by $p-R$, since

$$
(-R)^2 \equiv R^2 \equiv a \pmod p.
$$

In Quadratic Sieve, the modular square roots are used to identify the position of the sieving interval that is divisable by a prime factor in the factor base. Instead of trial-dividing every number in the sieving interval for each prime, the Tonelli-Shanks algorithm is used for calculating modular square root once for each prime and quickly identify the corresponding positions, which makes sieving more efficient.

\section*{Algorithm}
%3. Algorithm: Explain the algorithm or computational method used to solve the problem. Pseudocode may be used to clarify the main steps.

The primary intent of the algorithm is to find two non-trivial factors $a$ and $b$ whereas their product composes the integer $N$.
\[
    N = a \times b
\]
However, the integers $a$ and $b$ may not be useful. The expression can be rewriten by substituting the two variables into $a=x+y$ and $b=x-y$, where $x$ and $y$ are two new integer variables. Using the $x$ and $y$ representation, values of $a$ and $b$ can be uniquely identified and vice versa. The same product decomposition equation for number $N$ can be instead written as:
\[
    N = (x + y) \times (x - y) = x^2 - y^2
\]
Once the numbers $x$ and $y$ are found, the factors are given as $x+y$ and $x-y$

Quadratic Sieve algorithm bases on the idea of Fermat's method, but introduces multiple algorithmic enhancements. Considering the number $N$ is being multiplied with $k$ where $k>1$ such that:
\[
    k \times N = (x + y) \times (x - y) = x^2 - y^2
\]
or
\[
    x^2 \equiv y^2 \pmod N
\]
If the integer values $x$ and $y$ are obtained, one factor can be obtained by $a = \gcd(N, x+y)$, while the other is $b = N/a$.

Instead of searching directly for $x$ and $y$, the Quadratic Sieve defines the polynomial $Q$ below as:
\[
    Q(x) = x^2 - N
\]

For values of $x$ close to the integer square root $\lfloor \sqrt{N} \rfloor$, the value of $Q(x)$ is relatively small and therefore more possible to factor into small prime factors. In this case, the algorithm selects a \emph{factor base} given below:
\[
    \mathcal{B}={p_1,p_2,\ldots,p_m}
\]
consisting of small primes up to a specific bound. Recall that a value $Q(x)$ is  A value $Q(x)$ is called \emph{$\mathcal{B}$-smooth} if all of its consistent prime factors belong to the factor base.

For every $x$ in a selected sieving interval larger than $\lfloor \sqrt{N} \rfloor$, the algorithm evaluates all $Q(x)$ integer values, and filter out the $Q(x)$ values that are not $\mathcal{B}$-smooth.

A tiny example for visualizing the sieving interval can be constructed below, given that $N = 123$, and $\lfloor \sqrt{N} \rfloor = 11$. The quadratic polynomial used by the sieve is:
\[
    Q(x)=x^2-N=x^2-123
\]

The sieve interval can be written as:
\[
\begin{array}{c|c|l}
    x  & Q(x) = x^2 - 123 & \text{Factorization} \\ \hline
    11 & 121 - 123 = -2    & (-1) \times 2 \\
    12 & 144 - 123 = 21    & 3 \times 7 \\
    13 & 169 - 123 = 46    & 2 \times 23 \\
    14 & 196 - 123 = 73    & 73 \\
    15 & 225 - 123 = 102   & 2 \times 3 \times 17 \\
    16 & 256 - 123 = 133   & 7 \times 19 \\
    17 & 289 - 123 = 166   & 2 \times 83 \\
    18 & 324 - 123 = 201   & 3 \times 67 \\
    19 & 361 - 123 = 238   & 2 \times 7 \times 17 \\
    20 & 400 - 123 = 277   & 277
\end{array}
\]

For this example, a factor base can be choosen as:
\[
    \mathcal{B}=\{2,3,5,7\}
\]

Using the prime factorization in the array, only $x=11$ and $x=12$ are smooth, whereas other numbers are non-smooth since they contain prime factors larger than the given bound $7$.

However, manually sieving using prime factorization can be tedious and inefficient for large numbers, since this factorization algorithm recursively requires prime factorization. Trial division with all integers $Q(x)$ with each prime number in the factor base $\mathcal{B}$ isn't either the most efficient solution. In this case, the \emph{Tonelli--Shanks algorithm} can be used to sieve out the given $Q(x)$ that are divisible with each prime number.

For each prime $p$ in the factor base, the algorithm determines the values of $x$ for which
\[
Q(x)\equiv0\pmod p
\]
or moreover rewritten as:
\[
\begin{aligned}
    x^2 - N &\equiv 0 &\pmod{p}\\
    x^2 &\equiv N &\pmod{p}
\end{aligned}
\]

If $r$ is a solution to this congruence, then all values
\[
x\equiv r\pmod p
\]
and
\[
x\equiv -r\pmod p
\]
are candidates for being divisible by $p$.

By obtaining the roots from the modular equation, the positions of these roots can be marked in the sieving inteveral. Values that receive enough marks are candidates for being $\mathcal{B}$-smooth and are subsequently factored explicitly. The sieve adds the prime factor $p$ to the corresponding positions. Repeating this process for all primes in the factor base makes it possible to efficiently identify values of $Q(x)$ that are likely to be smooth.

For every smooth value, its factorization over the factor base is given for instance as:
\[
Q(x)=p_1^{e_1}p_2^{e_2}\cdots p_k^{e_k}.
\]
for the base $\mathcal{B}=\{e_1,e_2,\ldots,e_k\}$. The prime exponent can be written as $(p_1, p_2, \ldots, p_k)$ The parity of each exponent can be extracted out and form an exponent vector over Galois Field $\mathbb{F}_2$.

With the parity exponent vectors, using linear algebra, a selection vector
\[
\mathbf{x} =
\begin{pmatrix}
x_1 \\
x_2 \\
\vdots \\
x_m
\end{pmatrix},
\qquad x_i \in \mathbb{F}_2 = \{0,1\}
\]
can be calculated specifying which integer values of $Q(x)$ composes into a product that forms a perfect square. This can be done by solving the equation system 
\[
A^T \mathbf{x} = 0
\]
using Gaussian elimination over $\mathbb{F}_2$
\[
\mathbf v(x)=(e_1\bmod2,e_2\bmod2,\ldots,e_m\bmod2)
\]

The matrix $A$ can be formed by the smooth integer numbers in prime exponent vectors $\{n_1, n_2, n_3, \ldots, n_k\}$ over the given sieve interval. The rows of the matrices are the prime exponent vectors.
\[
A =
\begin{pmatrix}
e_{11} & e_{12} & \cdots & e_{1k} \\
e_{21} & e_{22} & \cdots & e_{2k} \\
\vdots & \vdots & \ddots & \vdots \\
e_{m1} & e_{m2} & \cdots & e_{mk}
\end{pmatrix}
\pmod{2}
\]

Notice that the number of columns of $A$ must be larger than the number of rows. The reason is that the linear equation system $A^T \mathbf{x} = 0$, has only a trivial solution vector $\mathbf{x} = \mathbf{0}$, meaning that none of the smooth numbers are selected.

For a non-zero solution to exist, the columns of $A$ must be linearly dependent. Since the columns are vectors in $\mathbb{F}_2^m$, there can be at most $m$ linearly independent columns. Therefore, choosing more smooth values of $Q(x)$ than the number of primes in the factor base
\[
k>m,
\]
guarantees that the columns of $A$ are linearly dependent. In this case, a non-trivial solution exist to
\[
A\mathbf{x}=\mathbf{0}
\]

When the selected integer values of the sieving interval can be calculated, the product decomposition equation earlier using modulo
\[
x^2 \equiv y^2 \pmod N
\]
can be written as
\[
    \left(\prod_{i=1}^{k} x_i\right)^2
    \equiv
    \prod_{i=1}^{k} Q(x_i)
    \equiv y^2
    \pmod N
\]

Using $a = gcd(N, x+y)$, one potential non-trivial factor can be solved out. Another factor can be subsequently solved out by division $b = N/a$.

The main computational advantage of the Quadratic Sieve is the sieving step using Tonelli-Shanks algorithm. Instead of attempting to factor each value $Q(x) = x^2-N$, the algorithm uses the small primes in the factor base to identify many smooth values and sieve the non-smooth factors out. The subsequent linear algebra combines these relations into the required congruence of squares.

\section*{Correctness}
% 4. Correctness: Explain why the algorithm produces a correct result. Where appropriate, provide a proof or justification of correctness.

The correctness of the Quadratic Sieve algorithm stems mostly from the congruence of squares equation. The smooth integer numbers $Q(x)$ of the given sieving interval makes it easier to find multiple $Q(x)$ where product of them produce perfect squares, since an unbounded prime base makes the matrix unnecessary huge and inefficient. 

Considering that for each selected value $x_i$, the quadratic polynomial gives $Q(x_i) = x_i^2 - N$, whereas its modular relation to $N$ can be written as
\[
Q(x_i) = x_i^2 - N\equiv x_i^2 \pmod N
\]

The product of the selected smooth integer values that produces a perfect square $\prod_{i\in S} Q(x_i)$ can be calculated as:
\[
    \prod_{i\in S} Q(x_i) \equiv \prod_{i\in S} x_i^2 = \left(\prod_{i\in S}x_i\right)^2
\pmod N
\]
where $S$ is the selected smooth integer values $Q(x)$ in the sieving interval.

\subsection*{Perfect product square}
The product of selected $Q(x_i)$ values is intended to be a perfect square, since the Gauss elimination over $\mathbb{F}_2$ finds a selection vector of selected smooth $Q(x_i)$ values to be a perfect square. 

Every $\mathcal{B}$-smooth value has a prime  factorization of the form
\[
Q(x_i)=(-1)^{e_{i0}}p_1^{e_{i1}}p_2^{e_{i2}}\ldots p_m^{e_{im}}
\]
where the prime base $\mathcal{B}$ is given as $\mathcal{B} = \{p_1, p_2, \ldots, p_m\}$ and the prime exponent vector for smooth number $i$ of the sieving interval as $(e_{i0}, e_{i1}, e_{i2}, \ldots, e_{im})$.

The exponent vectors on $\mathbb{F}_2$ are used since only the parity of the exponents is relevant when determining whether the product is a perfect square. A non-zero selection vector must in this case satisfy
\[
\mathbf{A}^T\mathbf{x}=\mathbf{0}
\]
The zero vector means that the sum of every selected exponent parity is even. This means that every prime number in the prime base occurs with an even total exponent, which means it is a perfect square. The sign exponent is also included in the vector, meaning the resulting product is positive as well. In this case, there exist an integer
\[
\prod_{i\in S}Q(x_i)=y^2
\]

Given that the product of the selected $Q(x_i)$ values, $\prod_{i\in S} Q(x_i)$, is a perfect square, the value $x=\prod_{i\in S}x_i$ and $y^2=\prod_{i\in S} Q(x_i)$, can be inserted into the modular equation $x^2 \equiv y^2 \pmod N$.

\subsection*{Quadratic congruence}
When both numbers $x$ and $y$ are obtained, the both factors to $N$ in the equation $x^2 \equiv y^2 \pmod N$ can easily be determined using greatest common divisor
\[
a = \gcd(N, x+y)
\]
while the other one through division $b = N/a$. The modular equation $x^2 \equiv y^2 \pmod N$ can be rewritten as
\[
(x+y)(x-y) = k \times N
\]
for some integer $k$.

This means that the factors $a$ and $b$ of $N$ are related to the two factors $x+y$ and $x-y$. The greatest common divisor can be used to determine which factors are shared between $N$ and $x+y$. Because of using greatest common divisor, the factors in $x+y$ that contributes to $k$ can be automatically removed, since only the factors that shares between $N$ and $x+y$ are kept.

Since $a$ divides both $N$ and $x+y$, it is necessarily a divisor of $N$. If the congruence is non-trivial, meaning that $x\not\equiv \pm y\pmod N$, then $a$ can be a non-trivial factor satisfying $1<a<N$.

The remaining factor can then be obtained directly from the original number $N$ by division.

\subsection*{Trivial factors being produced}
However, there are two cases where the algorithm may not produce a non-trivial factor. 

\begin{enumerate}
    \item First, the Gauss elimination may only produce the trivial zero selection vector if the amount of smooth $Q(n)$ in sieving interval is too small. In this case, larger sieving interal may mitigate the problem.
    \item Second, a non-trivial selection vector can produce a congruence where the gcd is $1$ or $N$. In this case, another linear dependency can be selected and the process repeated.
\end{enumerate}

Therefore, the Quadratic Sieve is considered to be correct that every factor returned by the final gcd calculation is a divisor of $N$. However, in some cases, the algorithm may fail to produce non-trivial factors, where $1$ and $N$ are produced.

\section*{Worked example by hand}
% 5. Worked Example: Provide at least one non-trivial example and demonstrate the algorithm step by step.

Consider a small non-trivial example $N=1057$ to be factorized. The square root of the number can be calculated as $\lceil \sqrt{1057} \rceil = 33$. This means that the sieving interval starts at $x=33$. Additionally, the bound for the factor base is calculated to $17$.

The algorithm begins by calculating the sieving base. A prime factor that isn't used in any of the sieving interval for the specific number can be discarded. This means that all prime numbers of the sieving prime base must have an arbitrary number $x$ to the modular equation $x^2 \equiv p \pmod N$. By applying the Euler's criterion on all the prime numbers up to $17$, the sieving base can be calculated as below:

\[\mathbb{B} = \{2, 3, 11, 13\}\]

As the sieving base is calculated, the non-smooth values are discarded from the sieving interval. By discarding the values from the sieving interval, the values must first be identified using Tonelli-Shanks algorithm for solving the modular equation $x^2 \equiv N \pmod p$ and then marked. Since the Tonelli-Shanks algorithm only works for odd prime $p$, the lowest number is $3$.

For $p=3$, the solution to the modular equation $x^2 \equiv 1057 \equiv 1 \pmod 3$ is $x \equiv 1$. The other base solution $x \equiv 2$ can be obtained by taking its negative modulo $p$. This means that all $x \equiv 1$ and $x \equiv 2$ should be marked for divisible by $3$, while the rest $x \equiv 0$ is not marked. In this case, Tonelli-Shanks algorithm will not be extended, since it is not the main focus of the algorithm.

The similar step works for the rest primes $11$ and $13$ as well.

After calculating the Tonelli-Shanks algorithm and marking the prime divisibility, the non-smooth numbers that cannot be divided by any of the prime numbers are discarded. The full interval can be shown below.

The interval is calculated from $x=33$ to $x=53$ with $20$ numbers, since it is not a large number. The bound number and the sieving factor base bound are chosen a bit arbitrary, since there is no golden rule for it. If the number is too small, only trivial factors will be produced. Otherwise, the computation might be too big. The sieving interval with only smooth numbers can be shown below:

\section*{Implementation and experiment}
% 6. Implementation and Experiment: Implement a small version of the algorithm and demonstrate it on suitable test cases. The implementation should support and illustrate the theoretical discussion rather than replace it. (for A grade only)

A prototype of the algorithm is implemented in Python, deliberately without any external libraries, so that every step discussed in the theoretical sections is visible in the source code. The purpose of the prototype is to confirm the theory rather than to compete with production factoring software.

\subsection*{Structure of the implementation}

The implementation is split into four modules that follow the structure of the theoretical discussion.

\begin{itemize}
    \item \texttt{util.py} contains the elementary number-theoretic helpers: \texttt{gcd} by Euclid's algorithm, \texttt{power\_modulo} for modular exponentiation by repeated squaring, \texttt{integer\_sqrt} for an exact integer square root by Newton iteration, and \texttt{prime\_list} for the sieve of Eratosthenes.
    \item \texttt{tonelli\_shanks.py} implements the Tonelli--Shanks algorithm as a single function \texttt{tonelli\_shanks(residue, prime)} which returns a solution of $x^2\equiv a \pmod p$, or \texttt{None} when no solution exists.
    \item \texttt{matrix\_util.py} contains the linear algebra over $\mathbb{F}_2$.
    \item \texttt{quadratic\_sieve.py} is the main module and contains the three phases \texttt{sieve\_factor\_base}, \texttt{sieve\_interval} and \texttt{quadratic\_sieve}.
\end{itemize}

Two design choices deserve comment, since they are where the theory translates most directly into code.

First, the factor base is not simply the list of all primes below the bound. The function \texttt{sieve\_factor\_base} keeps $p=2$ unconditionally and applies Euler's criterion to every odd prime,
\[
N^{(p-1)/2} \bmod p = 1 ,
\]
discarding $p$ when the test fails. This is exactly the argument from Step 1 of the worked example: a prime for which $N$ is a quadratic non-residue can never divide any $Q(x)$, so including it would only add a column of zeros to the matrix. Measured on the test numbers, the criterion removes roughly half of the candidate primes, for example $46 \to 22$ primes at bound $200$ for $N=1000036000099$, and $139 \to 64$ at bound $800$ for $N=10000004400000259$.

Second, the exponent vectors are not stored as lists but as machine integers. The function \texttt{prime\_to\_integer\_vector} sets bit $i$ of an integer when the exponent of $p_i$ is odd, so that an entire row of the matrix $A \bmod 2$ occupies one integer. Since addition in $\mathbb{F}_2$ is the XOR operation, as established in the background section, a row operation becomes a single \texttt{\^} instruction. The function \texttt{gf2\_gauss\_elimination} exploits this: it keeps a dictionary from the lowest set bit to the pivot row that owns it, and reduces each incoming vector against the existing pivots until either a new pivot bit is found or the vector becomes zero. A vector that reduces to zero is a linear dependency, and the accompanying mask, maintained in parallel over the identity matrix, records which relations were combined. This is the same bookkeeping as the augmented matrix $(A \bmod 2 \mid I)$ used by hand, expressed in bit operations.

\subsection*{Reproducing the worked example}

The prototype is first run on the number factored by hand, $N = 12620903$ with bound $40$, in order to check that the program and the manual computation agree. The factor base returned by \texttt{sieve\_factor\_base} is
\[
\mathcal{B}=\{2,\;7,\;11,\;13,\;17,\;19,\;29,\;31\},
\]
identical to the one derived by hand, and \texttt{sieve\_interval} with width $4000$ returns the nine relations
\[
x \in \{3554,\;3571,\;3611,\;3858,\;4143,\;4521,\;5305,\;7043,\;7088\},
\]
again matching the table of Step 2 exactly. The elimination finds three dependencies, in agreement with the rank $6$ computed by hand, and evaluating them in order gives

\[
\begin{array}{c|l|r|r|l}
\text{dep} & S & x & y & \gcd(|x-y|,N) \\ \hline
1 & \{3554, 3571, 4143\} & 1514864 & 1514864 & N \quad \text{(trivial)} \\
2 & \{3611, 3858, 5305\} & 9830525 & 9830525 & N \quad \text{(trivial)} \\
3 & \{3554, 3571, 3858, 7043, 7088\} & 12588218 & 8725705 & 6301 \\
\end{array}
\]

The first two dependencies are precisely the two degenerate cases identified in Step 5 of the manual computation, with the same values of $x$ and $y$. The third one splits $N$ and the program returns $6301$, whose cofactor is $12620903/6301 = 2003$. The successful selection set differs from the one used by hand, $\{3858, 4143, 7043, 7088\}$, but the two are not independent: their symmetric difference is exactly dependency $1$. Both therefore lie in the same null space and lead to the same factorization, which illustrates that the splitting selection vector is not unique.

The experiment also illustrates the first failure mode. Running the same number and bound with a shorter interval gives

\[
\begin{array}{c|c|c|c|c}
\text{width} & |\mathcal{B}| & k & k-m & \text{result} \\ \hline
1000 & 8 & 6 & -2 & \text{no factor} \\
2000 & 8 & 7 & -1 & \text{no factor} \\
3000 & 8 & 7 & -1 & \text{no factor} \\
4000 & 8 & 9 & +1 & 6301 \\
\end{array}
\]

The implementation returns immediately when $k \le m$, since the condition $k>m$ derived in the algorithm section is what guarantees that a non-trivial dependency exists at all. Only once the interval is wide enough to produce more relations than factor base primes does the sieve succeed.

N & \text{digits} & \text{bound} & |\mathcal{B}| & k & \text{factor found} \\ \hline

\subsection*{Comparison with trial division}

To show that the sieving machinery actually buys something, the prototype is compared against straightforward trial division by all integers up to $\sqrt{N}$, implemented in the same language so that the comparison is meaningful.

\[
\begin{array}{r|c|r|r|r}
N & \text{digits} & \text{trial division} & \text{quadratic sieve} & \text{speedup} \\ \hline
100160063 & 9 & 0.5 \text{ ms} & 16.7 \text{ ms} & 0.03\times \\
10002200057 & 11 & 6.1 \text{ ms} & 10.0 \text{ ms} & 0.6\times \\
1000036000099 & 13 & 67 \text{ ms} & 15.0 \text{ ms} & 4.5\times \\
100000980001501 & 15 & 671 \text{ ms} & 121 \text{ ms} & 5.5\times \\
10000004400000259 & 17 & 10400 \text{ ms} & 397 \text{ ms} & 26\times \\
\end{array}
\]

For the smallest numbers trial division wins, because the sieve has to build a factor base, run Tonelli--Shanks for every prime and allocate the whole interval before it can produce a single relation, and that fixed overhead dominates. The crossover occurs around $13$ digits. Beyond it the asymptotic difference takes over: trial division costs $O(\sqrt{N})$ and grows by a factor of about $10$ for every two extra digits, which is clearly visible in the column, whereas the sieve grows far more slowly.

Profiling the three phases confirms where the time is spent. For $N=10000004400000259$ the factor base construction takes $0.3$ ms, the sieving $342$ ms and the whole $\mathbb{F}_2$ elimination only $13$ ms, so sieving accounts for over $96\%$ of the runtime at this size. The bit-packed elimination is cheap precisely because of the XOR representation discussed above. This matches the claim in the algorithm section that sieving, not the linear algebra, is the computational core of the method at these sizes.

The choice of bound shows the expected trade-off. For $N = 1000036000099$:

\[
\begin{array}{r|r|r|r|l}
\text{bound} & |\mathcal{B}| & k & \text{time} & \text{result} \\ \hline
50 & 8 & 2 & 12.5 \text{ ms} & \text{no factor} \\
100 & 14 & 7 & 12.2 \text{ ms} & \text{no factor} \\
200 & 22 & 30 & 12.7 \text{ ms} & 1000003 \\
800 & 78 & 421 & 20.0 \text{ ms} & 1000003 \\
3200 & 226 & 1517 & 56.0 \text{ ms} & 1000003 \\
\end{array}
\]

A bound that is too small makes smooth values too rare to reach $k>m$, while an excessively large bound raises the number of relations that must be collected and the size of the matrix. The density of smooth values in the interval is low in absolute terms, around $0.1\%$ for the larger test cases, which is why the interval has to be several hundred thousand wide for a $17$-digit input.

\subsection*{Limitations of the prototype}

Three limitations were observed, all of them inherent to this minimal version rather than to the method.

\begin{enumerate}
    \item If $N$ is a perfect square, the offset $x=\lfloor\sqrt{N}\rfloor$ gives $Q(x)=0$, and the factorization loop in \texttt{sieve\_interval} does not terminate because dividing zero by a prime leaves zero. A perfect square should be detected beforehand, which is what the unused helper \texttt{perfect\_square} in \texttt{util.py} is for.
    \item If $N$ is prime, no non-trivial congruence can exist and the program correctly returns no factor, but only after exhausting the whole interval. A probabilistic primality test before sieving would avoid the wasted work.
    \item The prototype returns a single factor rather than a complete factorization, and gives no useful answer when $N$ has small prime factors or more than two prime factors. In practice the sieve is applied only after small factors have been removed by trial division.
\end{enumerate}

Furthermore, the implementation keeps the whole sieving interval in memory as a list of Python integers and strips prime powers by repeated division rather than by accumulating logarithms, which is the standard optimisation. Neither affects correctness, but both limit the sizes that can be reached. The largest semiprime factored here has $17$ digits, far below what an optimised implementation handles, which is sufficient to demonstrate the theory.

\section*{Discussion}
% 7. Discussion: Discuss the strengths and limitations of the approach and, where relevant, mention practical applications.

The Quadratic Sieve algorithm provides an efficient approach to
integer factorization by combining modular arithmetic, smooth
number generation, and linear algebra. Instead of directly
searching for divisors of a composite number, the algorithm
attempts to find a congruence of squares modulo the given
number. This approach allows multiple relations to be collected
and processed together, reducing the need for direct trial
division.

One of the main strengths of the Quadratic Sieve is its use
of smooth numbers. By selecting values close to the square
root of the number being factorized, the resulting quadratic
differences tend to be relatively small. This increases the
possibility of finding values that can be factorized using
only small primes from the factor base. The sieving process
further improves efficiency by identifying positions where
these small prime factors occur without having to perform
complete prime factorization on every value individually.

The factor base introduces a trade-off between the number
of smooth relations that can be found and the computational
cost of processing them. A larger factor base increases the
probability that a quadratic difference is smooth, since
more prime factors are allowed. However, it also increases
the dimensions of the exponent matrix and consequently the
cost of solving the corresponding linear system. A smaller
factor base reduces the cost of linear algebra but may
require a larger sieving interval to collect enough smooth
relations. Therefore, choosing an appropriate factor base
bound is an important part of optimizing the algorithm.

Another important strength of the Quadratic Sieve is the use
of linear algebra over $\mathbb{F}_2$. By reducing the prime
exponents modulo two, the algorithm transforms the problem
of finding a product that is a perfect square into a system
of linear equations. Gaussian elimination can then be used
to identify dependencies between the collected relations.
This is particularly useful because the algorithm can
process many smooth numbers together rather than relying
on a single relation. However, as the factor base and the
number of collected relations grow, the resulting matrix
can become large. For larger inputs, more advanced sparse
matrix algorithms may be required to maintain performance.

Despite its advantages, the Quadratic Sieve also has
limitations. Its performance depends heavily on finding
enough smooth values within the selected sieving interval.
If the factor base is too small or the interval is too
short, the algorithm may not collect enough useful
relations to find a dependency. Even when a dependency
is found, the resulting congruence of squares does not
necessarily produce a non-trivial factor. The greatest
common divisor may instead return either $1$ or the
original number $N$. In such cases, another dependency
must be selected and tested.

The algorithm also requires careful parameter selection.
The factor base bound, sieving interval, and number of
relations all influence the computational cost. A larger
interval can provide more smooth values, but it also
increases the amount of work required during sieving.
Similarly, increasing the factor base may reduce the
difficulty of finding smooth values while making the
linear algebra more expensive. These competing factors
make parameter selection an important consideration when
implementing the algorithm.

In terms of practical applications, integer factorization
is relevant to number theory and public-key cryptography.
The difficulty of factoring sufficiently large integers
is an important assumption behind the security of RSA.
The Quadratic Sieve demonstrates how mathematical
properties of quadratic residues and modular arithmetic
can be combined with computational techniques to solve
factorization problems more efficiently than basic
trial division for suitable input sizes. However, the
security of modern cryptographic systems relies on
numbers that are far beyond the intended scale of a
small educational implementation.

The worked example with $N=1057$ illustrates the main
mathematical ideas behind the algorithm. The factor base
is used to identify smooth quadratic differences, and
the corresponding exponent vectors are reduced modulo
two. Gaussian elimination then provides a dependency
that produces a perfect square. Finally, the congruence
of squares allows a non-trivial factor to be extracted
using the greatest common divisor. Although this example
is small enough to be calculated by hand, it demonstrates
the same fundamental process used for larger composite
numbers.

Overall, the Quadratic Sieve is an example of how
different mathematical concepts can be combined into
a practical computational algorithm. Its main advantage
comes from replacing direct factor searches with the
collection of smooth relations and the subsequent
identification of dependencies. Its main limitations
are the probabilistic nature of finding smooth numbers,
the computational cost of linear algebra, and the
sensitivity of performance to parameter selection.
These characteristics make the Quadratic Sieve both
an effective factorization method for suitable input
sizes and an instructive example of the relationship
between number theory and algorithm design.
